# 抖音数据抓取 · 维护说明

> **要用它，看 [`操作手册.md`](操作手册.md)。** 这份只讲"为什么这么造"和"坏了改哪儿"。

## 一句话

用你自己已登录的浏览器，读你自己抖音账号的创作者后台数据，落成按天累积的总表并出总览。只读，不发布，不代替登录。

## 日常命令

```
node scripts/check.mjs --launch   # 环境自检 + 启动浏览器
node scripts/daily.mjs            # 抓取 + 并表 + 出总览 + 记日志
node scripts/daily.mjs --force    # 强制重抓今天
```

退出码约定：`0` 成功 / `1` 失败 / `3` 今天已抓过（`daily.mjs` 据此提前收工）。

## 三个设计取舍

### 1. 零第三方依赖

**不依赖任何 npm 包，也不依赖 web-access 之类的外部 skill。** 只用 Node 22+ 自带的 `fetch` 和原生 `WebSocket`。

理由：这东西是要发给别人用的（学员、同行）。依赖越少，装起来的失败点越少。早期版本走的是 web-access 的 CDP proxy（`localhost:3456`），要额外装那个 skill、还要常驻一个 proxy 进程——现在全砍掉了。

### 2. 用专用浏览器目录，不用你日常那个

**Chrome 136 起禁止对默认用户目录开 `--remote-debugging-port`。** 所以 `browser.mjs` 永远用一个独立目录（默认 `~/.douyin-data/browser-profile`）。

代价是第一次要在那个窗口单独登一次抖音（登录态存在这个目录里，之后免登）。
好处是跟日常浏览器完全隔离，也避免了去动 `chrome://inspect` 那个开关。

> 顺带一提：通过 `chrome://inspect` 开关启用的调试模式，Chrome 会**关掉 HTTP 的 `/json` 接口**，只能走浏览器级 WebSocket + `Target.*` 命令。这正是原方案要写一个 proxy 的原因。自己指定 `--user-data-dir` 启动则保留完整的 `/json` 接口，客户端能简单很多。

### 3. 数据落盘不经过模型，也不起监听端口

用户给的原始方案（见下方"来源"）要在本机起一个临时 HTTP 服务接数据、用完删掉，并且明确记录了两条**不要走**的路：让 AI 逐字转录 base64（连错两次）、走浏览器下载（窗口失焦就静默丢文件）。

本方案走第三条路：用调试通道把字节**原样拉出来写文件**。落盘后浏览器端和本机各算一次 sha256 对账，对不上就停在取数那步、不并表。不经过任何人工转录，不起端口，不依赖下载和剪贴板。

### 4. MCP server 也是手写的，不用官方 SDK

`scripts/mcp.mjs` 自己实现了 MCP 协议（换行分隔的 JSON-RPC 2.0 over stdio），没引 `@modelcontextprotocol/sdk`。

理由跟第 1 条一样：一旦 `npm install`，双击启动那套就废了。而且这是个只有 6 个工具的服务端，协议面很窄。

**兼容两个协议年代**（都实测过）：
- **legacy**：`initialize` 握手 → `notifications/initialized` → `tools/list` / `tools/call`（2025-11-25 及更早，目前大多数客户端走这条）
- **modern**：`server/discover` 返回 `DiscoverResult`，每请求 `_meta` 带版本（2026-07-28 起）

版本协商采用「客户端报什么就回什么，不认识就回 `2025-06-18`」。

**踩过的坑**：stdout 是协议通道，任何日志都会把协议搞坏——所有调试输出必须走 stderr。

**Agent 交互上的一个关键设计**：`--wait-login` 默认在 CLI 是 360 秒（人用，等着扫码），
但 MCP 传 `0`。理由是不能把一个工具调用卡住几分钟——Agent 应该立刻拿到
`needs_login: true`，转告用户去扫码，然后再调一次。同理 `fetch.mjs` 用退出码
`4` 专门表示「需要登录」，跟普通失败区分开。

## 来源与差异

这套工具的起点是一份外部方案《抖音数据抓取全流程-小白版》（macOS + Obsidian + Qoder + WorkBuddy 那一套），2026-10-06 在本机重新实现。相比原方案的改动：

| 原方案 | 本方案 |
|---|---|
| 临时小服务接数据、用完删除 | 调试通道直拉，两端 sha256 对账 |
| 九步手工走 | `node scripts/daily.mjs` 一条命令，校验不过自动停 |
| 13:00 WorkBuddy 重抓覆盖 | 本机无 WorkBuddy，同日重抓走 `--force` |
| 16 列 | 17 列（末尾加 `media_type`，保住原 16 列顺序） |
| 账号信息写死在文档里 | 从 `/web/api/media/user/info/` 现取，可发给别人用 |

## 接口清单

| 用途 | 接口 | 坑 |
|---|---|---|
| 账号信息 | `GET /web/api/media/user/info/` | **未登录时是 HTTP 200 + `status_code: 8`**，只看状态码会把"没登录"误判成"没作品" |
| 作品清单 + 基础指标 | `GET /janus/douyin/creator/pc/work_list` | `aweme_id` 是字符串，不丢精度 |
| 单条深度指标 | `POST /janus/douyin/creator/data/item_analysis/item_performance` | 必须带 `involved_vertical` 否则返回空；不含当日发布作品；**`item_id` 是 int64，`JSON.parse` 会丢精度**，要从原始文本按序正则取 |
| 垂类参数 | `GET /janus/douyin/creator/data/item_analysis/involved_vertical` | |
| 账号总览 | `POST /janus/douyin/creator/data/overview/dashboard` | |
| 粉丝趋势 | `GET /janus/douyin/creator/data/overview/dashboard/fans` | |

接口变了**只改 `collect.js`**。

## 后台的数据缺口（不是 bug，别去修）

- 单条「整体完播率」`completion_rate_pct` 和「单条涨粉」`fan_gain`：后台只有账号级，没有单条接口。**留空，不做估算填充。**
- 图文作品（`aweme_type: 2`）：后台不给标题、不给时长，深度指标接口也只算视频。`collect.js` 会标成 `media_type=图文` 并把标题写成占位。
- 新作品当天没有深度指标：后台次日才算，`metrics_asof` 会空着。

## 已知限制

- 同一天重抓是**覆盖**（主键 = 抓取日期 + 作品ID），不会留两份
- 没有配置定时任务，靠手动或外部调度触发
- 未支持通过 `chrome://inspect` 开关启用的那种调试模式（HTTP `/json` 被禁用），只支持自己 `--user-data-dir` 启动的浏览器
- 数据目录跟着代码走，除非设了 `DOUYIN_DATA_DIR`。npx 用法由 `bin/douyin-data-mcp.mjs` 把数据目录指到 `~/.douyin-data/data`——因为 npx 的代码在缓存里，随时会被清掉
